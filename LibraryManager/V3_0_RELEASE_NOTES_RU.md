# AUTO SOUND HUNTER MANAGER 3.0.0 — Release Notes

Дата: 20 ноября 2026  
Платформа: Windows 10 x64 / Windows 11 x64  
Статус: **3.0.0 versioned build прошёл exact-head Linux и Windows CI; Portable ZIP и Installer EXE собраны и прошли smoke tests.**

## Назначение

AUTO SOUND HUNTER MANAGER — отдельное настольное приложение для безопасного импорта, инвентаризации, анализа, проверки и подготовки гитарных аудиоматериалов. Оно формирует согласованные каталоги и manifests для отдельного инструмента POP PUNK GUITAR ULTIMATE.

Manager **не является VST3-плагином и не воспроизводит гитарные партии**. В этом репозитории находятся Manager, его рабочие данные, проверки и контракты подготовки библиотеки; отдельный C++/JUCE playback engine здесь не объявляется.

## Основной интерфейс

Главный экран содержит ровно шесть основных действий:

1. IMPORT GUITAR
2. SCAN LIBRARY
3. START HUNTING
4. REVIEW QUEUE
5. BUILD LIBRARY
6. VERIFY / RECOVERY

Визуальная тема — NEON STAGE DEFAULT / SKIN-1: тёмная navy/black основа, electric blue и cyan для основных действий, purple и magenta для дополнительных акцентов. Sample Browser и Review Queue используют согласованную палитру.

## Работа с библиотекой и безопасность исходников

- Импорт создаёт отдельные проверенные SHA-256 копии внутри `Samples/Import Sample Guitar`; оригиналы не перемещаются и не изменяются.
- Сохраняются структура выбранных папок и относительные пути, необходимые для зависимостей SFZ.
- Незавершённый импорт откатывается без удаления исходников. Повторный импорт повторно использует только проверенные неизменённые копии; предыдущие версии сохраняются для сравнения и восстановления.
- Быстрое сканирование выполняет файловую инвентаризацию без обязательного хеширования или декодирования аудио. Глубокий проход проверяет SHA-256, форматы, SFZ и использует кэш.
- SFZ-аудит отслеживает sample mappings, диапазоны нот/velocity, include-файлы, отсутствующие зависимости и блокирует ссылки за пределы выбранного корня библиотеки.
- Недоступные каталоги и файлы отражаются в отчётах; частичный проход не маскируется под полный успешный результат.

## Анализ, извлечение и ручная проверка

- START HUNTING создаёт аудиоаналитические и классификационные кандидаты для нот, музыкальных фрагментов, повторяющихся ритмических областей, riff/phrase/melody и других структур.
- Извлечённые клипы и manifests размещаются в staging, связаны с исходным asset и сохраняют SHA-256, точные offsets, provenance и статусы.
- Повторяющийся ритм сам по себе не доказывает loop, riff, downstroke, meter или полную музыкальную фразу. Неизвестные поля остаются UNKNOWN/null и требуют проверки.
- Sample Browser и Review Queue позволяют слушать и проверять производные WAV, метаданные, границы, музыкальную роль, артикуляцию и лицензионные сведения.
- FACTORY допускает только ассеты с подтверждённым музыкальным review, разрешёнными правами, целостностью WAV/manifest и выполненными соответствующими mapping/readiness gates.
- Точные дубликаты устанавливаются по SHA-256. Похожие тембры и исполнения не удаляются и не объединяются автоматически.

## Подготовка библиотеки для POP PUNK GUITAR ULTIMATE

Полный цикл может формировать согласованные артефакты:

- `plugin_asset_catalog_*.json` — каталог и очереди десяти категорий подготовки библиотеки VST3;
- `plugin_library_structure_*.json` и `plugin_library_coverage_*.json` — логическая структура, покрытие и явные пробелы;
- `chromatic_pitch_map_*.json` — хроматическая карта 12 pitch classes;
- `performance_manifest_*.json` — связи ассетов и контракт будущих performance events;
- `reviewed_mode_assignment_index.json` — назначения, явно сохранённые оператором после проверки.

Категории подготовки библиотеки не являются дополнительными режимами Manager. Генерация JSON-каталога не означает, что отдельный VST3 уже реализован или что все ноты/артикуляции готовы к воспроизведению. Неодобренные данные остаются кандидатами; неизвестные velocity zones, note mappings, Pattern event timeline и Melody timing не выдумываются.

## Распределение, OTHER и восстановление

- Копирование одобренных ассетов выполняется транзакционно с проверкой SHA-256 и планом до фактического действия.
- Ошибка или отмена очищает только частичные назначения текущей транзакции; уже существующие проверенные файлы и исходники сохраняются.
- OTHER audit и routing используют отдельные проверяемые решения оператора.
- Очистка исходников имеет отдельный аудит, явное подтверждение и механизмы восстановления; обычное сканирование и подготовка не удаляют входные материалы.

## Windows-поставка

Поддерживаются два типа пакетов:

- **Portable ZIP** — автономная папка приложения с встроенным Python runtime, ресурсами NEON STAGE и маркером Portable-режима. Mutable data хранится в `UserData` рядом с приложением, а для недоступной для записи папки предусмотрен LocalAppData fallback.
- **Installer EXE** — per-user установка в LocalAppData Programs; маркер Portable-режима исключён, mutable data хранится в `%LOCALAPPDATA%\POP PUNK GUITAR Library Manager`.

Python, pip и PyInstaller конечному пользователю не нужны.

## Известные границы и обязательная ручная проверка

- Этот Manager готовит и проверяет библиотеку; он не заменяет отдельный VST3 playback engine.
- Аналитические гипотезы не являются автоматически подтверждёнными нотами, аккордами, артикуляциями или аппликатурами.
- Перед фактическим использованием оператору необходимо прогнать собственную папку Samples через импорт, сканирование, review, build и verify. Результаты на синтетических regression fixtures и CI не заменяют проверку реальной пользовательской библиотеки и прослушивание её производных.
- Никакой ассет не следует считать runtime-ready только потому, что он присутствует в JSON-каталоге; обязательны review, license, integrity и mode-specific playback gates.
